This pack adds BytePlus nodes to ComfyUI. It needs ComfyUI **0.31.0 or later** and works in both **Classic Canvas** and **Nodes 2.0** (Vue nodes).

Use **Nodes Manager** first. It downloads the pack from the [Comfy Registry](https://registry.comfy.org/nodes/ComfyUI-BytePlus-ModelArk) and normally installs its Python requirements. The **Comfy CLI** is the second option; a **release ZIP** is the last resort. To get a newer version later, see [Update](../update/).

## Install with Nodes Manager (recommended)

**Top-left dropdown > Extensions > Nodes Manager > search `byteplus` > Install**.

<Steps>

1. In the ComfyUI editor, open the **top-left dropdown** beside the ComfyUI logo. Choose **Extensions** to open **Nodes Manager**.
2. Keep **Node Pack** selected and search for **byteplus**.
3. Choose **ComfyUI BytePlus ModelArk, Speech, OmniHuman & MediaKit** from **byteplus-sa** (package ID: `ComfyUI-BytePlus-ModelArk`), then click **Install**. No separate ZIP download is needed.
4. If the pack is already installed, open its card and use **Update** when a newer release is available. Do not install a second copy.
5. Wait for installation to finish. Click **Apply Changes** if prompted, or restart ComfyUI. Reload the editor after the restart.

</Steps>

The **OmniHuman nodes** use this same pack and installation method. For the separate [BytePlus Avatar Studio app](../../custom-apps/avatar-studio/), also install `ComfyUI-BytePlus-Avatar-Studio` from **byteplus-sa** in the same search results; it requires the ModelArk companion.

In older ComfyUI layouts, **Manager > Custom Nodes Manager** opens the equivalent installer.

<Aside type="note" title="If a release is unavailable">
A Registry listing does not guarantee that every version is installable. If Manager reports no release for the selected option, check the package's versions and try another available release. Pending or flagged Registry versions may be unavailable; the CLI uses the same Registry and does not bypass that restriction.
</Aside>

## Install with the Comfy CLI

Use this second option if you prefer a terminal or cannot access Nodes Manager. With [comfy-cli](https://github.com/Comfy-Org/comfy-cli) configured for the **same ComfyUI installation you open**, run:

```bash
comfy node install ComfyUI-BytePlus-ModelArk
```

The command installs an available Registry release and its requirements. For an existing installation, use `comfy node update ComfyUI-BytePlus-ModelArk`. Restart ComfyUI and reload the editor afterwards.

## Install a release ZIP (last resort)

Use a ZIP only when Nodes Manager and the CLI cannot install the release you need.

<Steps>

1. Download the ZIP for the required version from [GitHub Releases](https://github.com/byteplus-sa/ComfyUI-BytePlus-ModelArk/releases).
2. Close ComfyUI. If a copy already exists, move it to a backup **outside `custom_nodes`**. Do not overwrite it or leave a second enabled copy.
3. Extract the pack to `ComfyUI/custom_nodes/ComfyUI-BytePlus-ModelArk/` in your active installation. The folder must directly contain `__init__.py`, `pyproject.toml` and `nodes/`, not another nested pack folder.
4. From your ComfyUI folder, install the requirements with **the same Python that runs ComfyUI**:

   ```bash
   python -m pip install -r custom_nodes/ComfyUI-BytePlus-ModelArk/requirements.txt
   ```

5. Start ComfyUI again and reload the editor. Keep your existing `user/` folder, workflows and `user/.env` credentials.

</Steps>

<Aside type="caution">
If you use a virtual environment or the portable build of ComfyUI, run `pip` from that environment. A `pip` from another Python installs the packages where ComfyUI cannot see them.
</Aside>

Manual ZIP extraction does not create Manager's `.tracking` metadata. The nodes can load while Manager still shows **Install**, and installing over that folder can fail. Use the recovery steps below to switch back to Manager.

## If the install path already exists

If Manager shows **Install** but reports `Install path already exists`, it has not recognized the existing folder as that Registry package. Missing `.tracking` metadata is one possible cause.

Close ComfyUI, move only the affected extension folder to a backup **outside `custom_nodes`**, then reopen ComfyUI and install it through **Nodes Manager**. Restart after installation. Do not remove `user/` or `user/.env`, and do not create an empty `.tracking` file as a workaround.

## If the BytePlus SDK is missing

The pack never installs packages on its own. If the BytePlus SDK (`byteplus-python-sdk-v2`) is missing or too old, the BytePlus nodes do not load. ComfyUI prints a message in its console instead. For a missing SDK it reads:

> BytePlus SDK is not installed; the BytePlus nodes are disabled. Install the requirements, then restart ComfyUI:

For an old SDK the message starts with *BytePlus SDK … is older than the required …* and ends with *Update it, then restart ComfyUI:*. Both end with the exact `pip install` command for your Python. Run it, then restart ComfyUI.

## Check that it worked

1. Double-click the canvas to open node search and type `Seedream`. The BytePlus nodes appear under the **BytePlus ModelArk** category.
2. Open **Settings** (the gear icon, or Ctrl+, / Cmd+,) and search for **BytePlus**. You should see a **BytePlus** page with a **Default credentials** section containing five key rows and three optional default endpoint rows for Seedance 2.0, Seedance 2.5 and Seedream 5.0 Pro.

If the Settings page is missing, [update the pack](../update/), restart ComfyUI and reload the page.

## Classic Canvas and Nodes 2.0

Both renderers show the same nodes and the same Settings page. Nothing needs to be turned on.
