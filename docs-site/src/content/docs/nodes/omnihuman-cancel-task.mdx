## What it does

Explicitly requests cancellation of an [OmniHuman 2.0](../omnihuman/) task. You need the original account's Vision AI key. The service only cancels queued tasks; a task already running may continue and be billed.

## Inputs

<NodeInputs id="BytePlusOmniHumanCancelTask" />

### Notes on inputs

- Supply an OmniHuman 2.0 task ID, not a ModelArk or LAS task ID.
- Connect an output to a consuming node to execute the request. An unused node does not run.

## Outputs

<NodeOutputs id="BytePlusOmniHumanCancelTask" />

### Notes on outputs

- `canceled` is true when the service accepts cancellation.
- A false result means the task already started or finished. Inspect it with [OmniHuman Task Result](../omnihuman-task-result/).
- In v0.11.0 and later, HTTP `400` with integer code `50217` also returns `canceled = false`. This is a cancellation refusal, not a stopped task. Other HTTP errors remain errors.
- The response contains no keys or signed URLs.

## Limits and tips

- Only tasks in `in_queue` can be canceled. The [official API](https://docs.byteplus.com/en/docs/byteplus-vision/omnihuman-2-0-video-generation) returns code `50217` when a task already started.
- Interrupting a generation node stops local waiting and does not automatically call this node.
- Cancellation is not a promise of a billing refund.

## Common errors

| Message | What to do |
|---|---|
| `No Vision AI API key is set` | Save the original task account's Vision AI key in **Settings > BytePlus**. |
| `Invalid OmniHuman input` | Check the accepted OmniHuman 2.0 task ID. |
| `OmniHuman request failed` | Check account permissions and inspect the task's current state. |
