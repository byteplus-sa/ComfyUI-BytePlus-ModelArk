## What it does

Creates a video with BytePlus Seedance that starts at a first frame image. Add a last frame and the video ends there. The prompt describes the motion in between. You need a first frame, either as an image or as an asset ID or link.

The node bills for every video it generates and waits until the task finishes. It does not save anything itself: connect **Save Video** to keep the result.

## Inputs

<NodeInputs id="BytePlusSeedance2FirstLastFrame" />

### Notes on inputs

- **Frames:** use either `first_frame` or `first_frame_asset_id`, never both. The same rule applies to the last frame. The first frame is required, the last is optional.
- **Asset IDs and links:** the `*_asset_id` fields take an asset ID, `asset://<asset_id>` or an https link to an image. With IAM keys saved in **Settings → BytePlus**, an asset ID is checked to be active and an image. Without them it is sent unchecked. A link is only checked against its file extension.
- **Aspect ratio:** on Seedance 2.5 the video keeps the aspect of the first frame. On Seedance 2.0, 2.0 Fast and 2.0 Mini the `ratio` setting is back and defaults to `adaptive`. When you connect images (no asset IDs) on these models, the node crops them from the center and resizes them to the exact output size of the chosen `resolution` and `ratio`. With `adaptive` it uses the supported ratio closest to the first frame.
- **Models:** the options match [Text to Video](../seedance-2-5-text-to-video/): 2.5 (480p to 1080p, up to 30 s), 2.5 Premium (4k only), the two Draft options (480p only) and 2.0, 2.0 Fast and 2.0 Mini (up to 15 s).
- **Several videos:** raise `generation_count`. The tasks run in parallel and generation N uses `seed` + N.

## Outputs

<NodeOutputs id="BytePlusSeedance2FirstLastFrame" />

### Notes on outputs

- The `last_frame` output is the last frame of each generated video. It is not the `last_frame` image you connected.
- With `generation_count` above 1, `VIDEO` is a list: the next node runs once per video, and `last_frame` holds their last frames as one batch in the same order.
- `draft_task_id` is for the two Draft models. Send it to [Draft to Final Video](../seedance-2-5-draft-to-final/). Linking it while another model is selected stops the run.
- With `non_blocking` on, the first run returns at once with the task IDs in `response` and no video, so nodes connected to `VIDEO` or `last_frame` are skipped. Run the node again to collect the finished video.

## Limits and tips

- Each connected frame needs at least 300 pixels on both sides and an aspect ratio between 0.4 and 2.5. On Seedance 2.5 a frame with a side above 6000 pixels is scaled down.
- Connected frames are sent inside the request, so nothing is uploaded and no Comfy.org login is needed.
- Interrupting cancels tasks that are still queued. A task that is already running cannot be cancelled: it finishes and is billed. The node shows the task IDs, and [Video Query Tasks](../video-query-tasks/) finds them again. See [Interrupts and cancelling](../../concepts/interrupts/).
- A draft can be rendered into the final video for 7 days after it was created. Set `control after generate` under `seed` to `fixed` so the draft is not generated again. See [Draft mode](../../concepts/draft-mode/).
- With `generation_count` above 1, every video is billed. See [Billing and cost](../../concepts/billing-and-cost/).
- For several images, audio or an existing clip, use [Reference to Video](../seedance-2-5-reference/).

## Common errors

| Message | What to do |
|---|---|
| `Either first_frame or first_frame_asset_id is required.` | Connect a first frame image or fill in `first_frame_asset_id`. |
| `Provide only one of first_frame or first_frame_asset_id, not both.` | Clear one of the two. The same message exists for the last frame. |
| `Reference image ratio must be between 0.4 and 2.5` | Crop the frame so its width divided by height is inside that range. |
| `Reference image width/height must be between 300px and 6000px` | Scale the frame so both sides are at least 300 pixels. |
| `Enter a prompt.` | Type a prompt. An empty prompt is refused before anything is sent. |
